## Approved glTF loader

Tinygltf was approved by TA Bryce Joseph in class on September 21, 2026 (Special OH for Project 3), as reported by the student in this session on October 1. The assignment recommends tinygltf and permits third-party loading code with approval. Instructor Matthew Schwartz separately confirmed on October 1 in Ed post #78, “tinygltf approved package?”: “Yes- tinygltf is OK to use for the glTF extra credit!” The student supplied the confirmation screenshot; its hash is recorded in the package register. This authorization is limited to the named loader; it does not authorize other internet implementations or another student's code.

Only `tiny_gltf.h` and its MIT `LICENSE` were fetched, unchanged, from the official [tinygltf v2.9.7 release](https://github.com/syoyo/tinygltf/tree/v2.9.7), revision `488a70a3df62a4df1a736e9e56fb8836580c4888`. [approved-third-party.json](approved-third-party.json) records the URLs, exact byte hashes, license and approval scope. Its examples, models, tests and other dependencies were not imported. The loader reuses the JSON and STB headers already supplied by the approved starter. Our glTF-to-triangle integration, validation, generated assets and performance tooling are original project code.

The wrapper disables tinygltf's native image decoder/writer because this importer uses scene-assigned materials and textures. Its original callback does not decode glTF image pixels; external image files are still recorded for checkpoint identity. No STB or JSON upgrade is imported to add APIs absent from the starter.

Own previous-project source may be reused from Project 1 revision `d0df4d4e1f5985ef936c5ddc11a95331df27908b` and Project 2 revision `6a13e6fbe3a998c67fdbbdbe6643a5b4c4233b31`. Reuse is limited to code authored for those projects; their bundled external dependencies are not implicitly authorized here.

`stream_compaction/device_scan.cu` and `device_scan.cuh` extract our own Project 2 scan implementation from `stream_compaction/shared.cu` and `shared_internal.cuh`. They do not import the previous project's third-party timing wrappers. This reuse is documented separately from newly written renderer code; no additional feature points are claimed for the previous scan work.

Sampler version 2 reuses the unchanged official starter's `utilhash` in `src/intersections.h`. Its ordered seed/pixel/sample/bounce/dimension composition and conversion to an open-interval sample are original implementation. The inherited hash remains classified as starter code.

Sampler version 3, the prime-base generator, digit scrambling, exposure-time sampling, swept motion bounds, and their host/device tests are independently authored. No external random-number generator, scrambling table, motion implementation, or sampling code was imported.

`scripts/generate_gltf_assets.py` serializes our own canonical OBJ geometry into glTF/GLB assets using the Python standard library. It does not use a third-party converter or downloaded model. The corresponding glTF scenes, validation fixtures, measurement drivers and interaction recorder are original project work. Image assets continue to come from our original asset generator.

`scripts/remote.py` is adapted from our own Project 2 transfer helper, retaining trusted SSH host-key verification and local-only connection metadata. Original meshes and BMP textures are generated by `scripts/generate_assets.py`; no downloaded models or textures are used in the new showcase scenes.

Our earlier extension added original histogram/scan/scatter material queues, specialized CUDA shading kernels, Russian roulette transport, fluted-body and swept-knot geometry, and analytic marble and staggered-cell textures. Their equations are independently translated into implementation. No external noise, mesh-generation, integrator, queue, or model-loading implementation is imported. The previous fully reviewed local revision is `589fecacad54b359a854a825020d69216d099c45`; its reviews are historical and do not accept the current sampling, motion and glTF additions.

The shared checker-parity helper and its host/CUDA boundary regressions are independently authored. They correct the accepted-input overflow found during final review without importing a checker implementation or changing ordinary float-first cell boundaries. All current rendering evidence is refreshed after that fix.

## Completion acceptance

> Using third-party code without its approval, including using another student's code, is an academic integrity violation, and will, at minimum, result in you receiving an F for the semester.

This is a hard acceptance gate. Never use another student's code. Never copy or adapt an unapproved internet implementation. The explicitly authorized official starter and its existing dependencies, and the specifically approved unchanged tinygltf loader described above, are the only third-party exceptions. Preserve their credits and identify them as inherited or approved package code. Our own Project 1/2 implementation may be reused with revision/path provenance. Add no other third-party implementation or dependencies.

Two independent reviewers each perform two complete audits after the source, tests, renders, benchmarks, and README are finished. At least four clean reports must identify the same frozen whole-deliverable hash. Planning reviews do not count. Any subsequent deliverable modification resets both rounds for both reviewers. Unresolved provenance, unapproved-code, or correctness findings prevent completion. Review reports remain outside the frozen deliverable.
